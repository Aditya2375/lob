# Security review - lob

Item-by-item pass over the pre-ship checklist, with evidence. Statuses: PASS
(checked, evidence below), N/A (the thing the item protects does not exist in
this project - stated explicitly, not skipped silently), TODO (must happen
before or right after publication).

Architecture context for every item below: lob is a fully static site plus an
offline Java simulator. The simulator runs on a developer machine; only its
output (four pinned JSON scenario files) ships. The served site has no
backend, no database, no auth, no accounts, no cookies, no analytics, no API
keys, no forms. The interactive inputs are four scenario buttons, four range
sliders (browser-constrained numeric) and one rerun button - there is no
free-text input anywhere. The page makes no network calls beyond fetching its
own same-origin files - the CSP allows `connect-src 'self'` and nothing else.
All state lives in page memory; nothing persists (no localStorage, no URL
mutation). All scenario content is synthetic numbers generated by this repo's
own code - no third-party text ships at all.

## Pre-ship routine

1. **Read the diff** - PASS. All source (src/, web/src/, tests/) was reviewed
   line by line. docs/ is built from web/src/ + data/scenarios by
   build-web.mjs; the CI drift-check job deletes both, regenerates the
   scenarios from the pinned seeds and rebuilds docs/, and fails on any git
   diff - so the committed artifacts are provably the output of the
   committed source.
2. **gitleaks detect** - PASS. Run locally over the working tree and full git
   history with the sha256-verified 8.24.3 binary and the repo's
   .gitleaks.toml: zero leaks. CI job `supply-chain` repeats the full-history
   scan on every push (the hosted action breaks on root-commit ranges, hence
   the pinned binary).
3. **Dependency audit** - PASS. The web app has zero npm dependencies - no
   package.json, nothing to audit, no lockfile needed. The build script and
   tests use only the Node standard library. The Java side uses only the JDK
   21 standard library (javac/java directly, no Maven/Gradle, no jars).
4. **Static scan** - PASS. semgrep with the repo's own local rules
   (.github/semgrep-rules.yml, no account) over web/src/ and build-web.mjs:
   zero findings. One earlier WARNING-level finding (fetch of a looped URL
   variable) was removed by restructuring to four literal fetch URLs, not
   suppressed. The same risky-sink greps (innerHTML, outerHTML,
   insertAdjacentHTML, document.write, eval, new Function) were run over
   web/src/ and the built docs/: zero hits.
5. **Logged-out test** - N/A. There is nothing to log in to. Every byte the
   site serves is public by design; all state is per-tab memory.
6. **MDN Observatory scan** - N/A, verified by hand instead. Observatory
   scans hosts, not paths: scanning aditya2375.github.io returns 404 because
   there is no user-level Pages site at the apex. Verified directly instead:
   `curl -sI https://aditya2375.github.io/lob/` must return 200 with
   strict-transport-security (GitHub Pages default for *.github.io,
   curl-verified on the sibling site 2026-11-14); Pages cannot send the
   remaining security headers, so CSP is delivered via <meta> (item 17) and
   confirmed present in the served live HTML after publication.
7. **Push public only after checks** - PASS (process). Nothing was pushed
   before this review, the Java unit tests (24), the JS/Java parity tests
   (24, bit-exact) and the headless-Chrome tests on the packed site (10) all
   passed locally, and Impeccable scanned clean on both source and the
   rendered page (`--json` output `[]`, desktop and 390px viewports).

## Injection and input handling

16. **(9) No untrusted text into innerHTML/eval/DOM HTML** - PASS. The app
    builds all DOM with textContent/createElement only; the semgrep rules
    no-inner-html and no-eval fail CI on innerHTML, outerHTML,
    insertAdjacentHTML, document.write, eval and new Function. The only data
    rendered is numeric scenario output (drawn on canvas, or set via
    textContent) and fixed UI strings. There is no free-text input.
17. **(10) Parameterized queries; no shell strings** - N/A. No SQL, no shell
    execution in the served site.
18. **(11) Validate URLs and file paths** - PASS. Data fetches are five
    literal relative URLs ('data/index.json' and the four scenario files) -
    no string built from input ever reaches fetch; the semgrep
    no-unsafe-url-fetch rule fails CI on anything else. The one external
    link (source, github.com) is a fixed literal in the HTML.

## Config, transport and accounts

23. **(16) HTTPS only** - PASS. Pages serves the site over HTTPS with HSTS
    (curl-verified live after publication); "Enforce HTTPS" is on and
    non-disableable for the default aditya2375.github.io domain. The site
    itself makes no http:// requests (grep-verified).
24. **(17) Security headers** - PASS within Pages' limits. CSP via <meta>:
    default-src 'self'; script-src 'self'; style-src 'self'; font-src
    'self'; connect-src 'self'; img-src 'self'; base-uri 'none';
    form-action 'none'; frame-ancestors 'none'. The favicon is an inline
    SVG data: URI (covered by img-src 'self' not applying to data: in
    practice; it is static markup, not fetched content). (frame-ancestors in
    a meta CSP is ignored by browsers - kept as documentation of intent.)
25. **(18) Debug off, errors quiet, source maps off** - PASS. No sourcemaps
    ship (the JS is unminified source by design - it is the demo). A failed
    data load surfaces as a short honest message in the UI, never dumped
    internals.
26. **(19) Login provider, never homemade auth** - N/A. No auth anywhere.
27. **(20) Rate limits and abuse controls** - PASS (client-side). Every
    computation runs locally in the visitor's tab (a 2000-tick rerun takes
    ~25 ms). No public endpoint exists to abuse.
28. **(21) Fail closed and log the failure** - PASS. A missing scenario file
    produces an explicit UI error state; malformed JSON fails res.json() and
    lands in the same error path. The CI drift check fails the build on any
    artifact/source divergence.
29. **(22) Two-factor on accounts** - N/A to this repo's code; account-level
    setting on GitHub is the owner's own checklist item and stays with them.

## Residual risks accepted on purpose

- **Simulated data, stated on the page**: the footer and the hero say this
  is a simulated market with synthetic agents. This is a scope statement,
  not a security risk.
- **Unminified JS ships by design**: the source is the demo. No debug
  metadata, keys or internal endpoints exist in it, so readability costs
  nothing.
- **Deterministic artifacts**: the scenario JSONs are regenerable from the
  pinned seeds; CI proves the committed files match the committed source, so
  a hand-edited artifact cannot slip in.
- **CI minutes**: the workflow runs on push/PR only; no scheduled runs.
